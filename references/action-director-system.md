# 武戏导演系统

本系统用于身体对抗、追逐、争夺、突围等动作场次，先把剧情任务展开为可供用户裁决的动作方案，再设计分镜与派生提示词。首次处理本类场次时完整读取 [武戏叙事与动作摄影](action-direction-knowledge.md)。非动作场次不加载；普通情绪性走位、人物转身或无对抗的日常动作仍按现有表演与容量系统处理。

## 1. 权限与两种输入

剧本明确写出的事件、动作、先后、胜负、伤情、武器、关键物品归属、人物能力和结果是权威事实，必须保留。将动作方案区分为：

- **明确动作**：剧本或已锁定资料已确定的动作；只能在不改变它的前提下安排可见性、走位细节与镜头。
- **待编排空白**：剧本只概括“交手、追逐、争夺、突围”等过程，尚未确定中间动作；提出一版候选动作方案，标明新增的动作过程和推导依据，逐场得到用户明确接受后才能写第②步分镜简稿。
- **超出编排权限**：改变胜负、增减关键事件、显著改变人物能力、增加武器或特技、造成新伤情／场地破坏／关键物品状态变化；单列待裁决，不混进普通动作过程。

用户允许“逐场确认候选动作方案”。因此无论正常／工业模式，概括性武戏的动作方案都要明确展示并获得本场接受；单独选择“工业模式”、沉默或确认其他分析内容，不代表接受尚未明确确认的动作编排。用户在同一回复中明确接受本场方案并选择工业模式，可以一次完成两个决定。方案修订后，只有受改动的动作编排需要重新确认。工业模式随后可自动完成第②至⑤步，但不能暗中新增或更改已确认动作方案的实质因果、能力与结果；必要变更须回到本场方案确认。

若剧本动作已写清且不需补充实质过程，按原五步权限执行，在第①步注明“明确动作，无待确认编排”。正常模式仍确认第①步；工业模式由用户按原规则选择。

## 2. 项目动作风格

第0步发现项目含实质性武戏时，在全片基线中提出动作风格并请用户确认；项目可选择“写实近身／追逐”“武侠／功夫”或用户自定义、混合风格。记录在 `storyboard_global_analysis.md` 的“动作风格与能力边界”下，供相关场次继承：

```markdown
## 动作风格与能力边界
- 项目风格：写实近身／追逐 / 武侠／功夫 / 自定义或混合
- 动作展示重点：
- 人物能力与世界规则：仅记录剧本或用户确认的内容；未知标未知
- 受力与伤情呈现原则：
- 摄影与剪辑倾向：允许按单场目的例外，不锁死景别或切速
- 禁止擅自引入：
```

用户未指定时可提供有剧本依据的一版建议，但不得把武侠、超常能力、写实伤害程度或具体武术门派默认为事实；风格未确认前只做候选分析，不以猜测风格定稿武戏。同项目不同场次可在第①步提出有依据的风格例外并确认，不自动改变全片基线。

## 3. 第①步：场次动作方案

在现有本场分析里增加紧凑的“武戏导演”区块，并随本场工作卡保存，不另建项目事实文件。先明确剧情锁定项，再给一版有因果的动作方案；不要预设回合数或强迫每场反转。

```markdown
### 本场武戏导演
- 来源：剧本明确动作 / 已确认动作 / 待编排空白（逐项标明）
- 双方任务与阻碍：
- 锁定的结果、能力和不可改变条件：
- 空间条件：已确认的出口、障碍、活动区、可用物与未知区
- 起始关系：人物位置、朝向、持物、身体状态；未知标未知
- 动作段落候选：每段写“尝试→应对→位置／平衡／信息变化→可见结果”，只写本场实际需要的段落
- 优势或策略变化：触发事件与人物代价；不发生则写无
- 结束状态与进入下一场的接口：
- 待确认编排：逐项列出剧本未写明的过程
- 超出编排权限或无法判断的事实：
```

动作段落是导演方案，不是现实格斗教学。使用观众能观察到的运动、距离关系与结果表达，不机械罗列招式名称；用户明确要求特定招式或武术体系时，核对其与项目能力、场地和动作目的是否相容。没有依据的地图、隐藏道具、人体能力或精确距离保持未知。

提案后明确询问用户是否接受本场候选编排及需要修改之处。用户接受后，才将方案标记为“用户确认”并允许进入第②步；工业模式的选择与动作方案接受分别记录来源。未接受前不得把候选动作写入正式分镜、正式连续性或锁定事实。当前场中断续作时从工作卡判断编排是否已接受；没有明确记录则再次展示待确认方案。

## 4. 第②步：从动作段落到镜头结构

基于已确认动作方案，按因果与观看需要组织镜头，而不是先填镜号再凭空制造动作。每一关键段落检查：

1. 观众需要看懂的任务、障碍或优势变化是什么；
2. 当前空间线索是否足够，人物、目标物和出口是否有已确认关系；
3. 发起、应对、接触或落空、结果中哪些必须同镜可读，哪些可以跨镜延续；
4. 每镜起止动作阶段、人物朝向和持物状态能否接上；
5. 呼吸、蓄势、失衡、恢复、信息读取所需时长是否真实容纳。

景别、运镜、切速和是否完整展示身体动作由本场叙事决定。只有空间方向或动作结果需要重新建立时，安排承担该功能的镜头；不规定每场必须全景开头、长镜头或快切。改变已确认动作因果的镜头方案返回第①步动作方案；只改变镜头数、主要景别、主运镜或动作／对白分配，按原第②步确认边界处理。

## 5. 第③至⑤步：动作可执行性自检

逐镜检查下表，只记录影响本场的状态变化；没有变化不填满表格。候选检查结果在第③、④步只用于内部校验，第⑤步通过原事务写回正式事实源。

| 检查对象 | 要核对的事实 |
|---|---|
| 攻防因果 | 动作从何而来、对方如何应对、接触／落空后为何出现这一结果 |
| 空间方向 | 人物、目标物、障碍、出口和摄影机位置是否允许该动作及切镜后的方向 |
| 身体状态 | 站立／倒地、朝向、持物手、负重、失衡、受限部位与疲劳是否正确延续；只在叙事相关时追踪 |
| 关键物品 | 持有人、交接、落点、可见性和场末归属是否一致 |
| 物理与风格 | 受力、惯性、反作用与恢复是否符合本项目已确认的能力和写实／武侠边界 |
| 观众读取 | 必要的意图、接触、结果或人物判断是否能在当前景别、遮挡、光影与时长下被理解 |
| 容量 | 串行动作、真正可同时发生的动作、移动、停顿与结果读取是否被合理估时 |

人物只是短暂失衡、换手或改变朝向，且跨镜、跨场不再产生后果时，在当前镜头或工作卡中核验即可；会影响后镜或后场的状态，按连续性系统第⑤步差异记录。伤情、衣物、妆发、固定光源和关键物品仍由各自现有事实源管理，不复制第二份状态表。

无法在已确认空间或能力边界内拍出方案、或容量过载需要改变动作因果时，暂停并给出具体冲突与最少可选改法。正常模式按原第②步及动作方案边界确认；工业模式可以在镜头表达内返工，不能绕过用户对概括性武戏动作方案的逐场确认。

## 6. Seedance 与其他派生输出

只从第⑤步已定稿分镜编译动作，保留发起、应对、接触／落空、受力／运动结果、持续状态及镜头接口。为消除指代或时序歧义，可改写表达而不改变事实；正式分镜没有的攻击、防御、特技、破坏或伤情不得在提示词阶段补造。单次生成段容量不足时只报告适配风险，按原容量模块处理。动作与光学、表演、空间、灯光、声音的指令须能同时成立。
