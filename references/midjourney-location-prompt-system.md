# Midjourney 场地图提示词系统

将已确认的场地、空间与光影事实编译为一版中文 Midjourney 场地图提示词。本系统按需加载，不重新拆镜或直接生成图片。默认目标接口为 LibTV 的 Midjourney 输入框；用户明确要求原生 Midjourney 格式时，才按其当前要求处理参数。

## 1. 触发与边界

仅在用户明确要求 MJ、Midjourney、主建立视角、反方向场地图或场地光影版本提示词时调用。普通分镜制作不自动加载、不自动输出。

先识别入口：

- `MJ_LOCATION_ONLY`：只处理当前场地，不要求完整剧本、人物表或分镜基线。
- `MJ_IN_PROJECT`：读取现有 `storyboard_global_analysis.md`、`storyboard_locations.md` 和相关场次资料，不重新启动完整分镜流程。

两个入口均按本机资产库规则定位项目，提示词按场次或跨场场地归档。旧规则“当前稳定工作目录下的 `storyboard-mj/`”只用于识别既有资料，不再作为新任务默认目录；不静默搬动旧项目。

只使用以下已确认来源：用户当前明确指令、`storyboard_locations.md` 中已锁定场地事实、空间参照表、用户确认的场景图及其事实、场地基础光影、相关场景灯光卡、全片光影圣经。

不得：

- 重新理解或改写剧本；
- 擅自新增门窗、家具、灯具、装饰或叙事道具；
- 把推断、图片偶然元素或未知区域写成事实；
- 加入剧情人物，除非用户明确要求无身份比例参照人物；
- 输出其他图像或视频提示词系统、JSON或API字段；
- 输出多个版本、修图提示词或失败纠偏方案；
- 直接生成图片。

默认输出中文、一项任务一版、横向16:9电影画幅，不输出参数。用户明确要求原生 Midjourney 格式或其他画幅时，以当前指令为准。

主系统可以根据剧本中的场地功能提出一版功能性空间方案，包括必要结构、活动区、通道和少量剧情必需元素。所有提议必须标记“待确认”，经用户确认并写入 `storyboard_locations.md` 后才成为本模块可编译的正式事实。

## 2. 三种任务

### MAIN_VIEW

首次建立场地空间基础图。必须先确认场地身份、时代地域、核心结构、明显元素、人物活动区域、主视角、摄影机位置、观察方向、前中后景、场地基础光影和禁止出现内容。场地基础光影可依据全片光影圣经和场地功能建立，不要求先完成某一具体场次灯光卡。

默认 `NO_REFERENCE`。用户主动提供建筑、材质或时代参考时可用 `REFERENCE_OPTIONAL`。目标是在一个视角中清楚展示核心功能区、关键固定元素、通道、活动区域和主要光线入口。保持无人，避免极端广角、荷兰角、过度浅景深和遮挡空间的大面积前景。

### REVERSE_VIEW

在用户已选定并确认主建立图后，生成同一场地的对向建立视角。默认 `REFERENCE_REQUIRED`，指定参考图必须是该场地已确认主建立图。

调用前必须具备：主图文件或明确图片标识、主图事实卡、主图新增元素的用户裁决、反方向摄影机位置与观察方向、当前左右关系、当前前中后景以及新看到区域的已确认事实。

反方向不是机械镜像。门窗和固定元素在新画面中的位置由空间关系决定，可以移出画面或被遮挡；不得复制主图的画面坐标，也不得把未知背面补成新房间。

### LIGHTING_VARIANT

保持同一张已确认基础场地图的视角、构图和空间事实，只改变剧情需要的时间、天气或光源运行状态。默认 `REFERENCE_REQUIRED`，必须指定对应视角的基础场地图。

允许变化项必须明确；除此之外，摄影机、构图、左右关系、门窗、固定家具、材质、空间尺度和物体数量全部保持。

特定场次的光影版本必须等该场灯光卡确认后生成。通用时间或天气版本可使用场地档案中已确认的场地基础光影。

### 是否阻塞分镜

- 场地图只作为气氛参考：不阻塞分镜。
- 场地图被指定为正式空间依据：主图选定、视觉分析和空间事实确认前，相关场次不得进入正式分镜。
- 分镜已经定稿后才选定场地图：不得反向覆盖分镜，只列出空间冲突等待用户裁决。

## 4. 参考图规则

- `NO_REFERENCE`：无需上传参考图，默认用于首次主建立视角。
- `REFERENCE_REQUIRED`：必须使用指定参考图，默认用于反方向视角和光影版本。
- `REFERENCE_OPTIONAL`：仅在用户主动提供适用参考时使用；不得自行索要无关参考。

参考需求与参考类型是两个独立字段。每张图必须指定一种主要类型：

- `CONTENT_REFERENCE`：提供场地身份、已确认结构、固定元素、构图关系、材质和色彩。主建立图、同视角基础图通常属于此类。
- `STYLE_REFERENCE`：只提供色彩、媒介感、质感、影调和视觉风格，不提供门窗、家具、站位或空间结构。
- `LAYOUT_REFERENCE`：提供平面关系、门窗、通道、相对方位和已标注尺度；不提供材质、装饰和最终光影。

同一文件确实承担多种作用时，分别列出每种类型及权限，不能只写“参考图”。氛围图默认是 `STYLE_REFERENCE`；平面图默认是 `LAYOUT_REFERENCE`；已确认主建立图默认是 `CONTENT_REFERENCE`。

参考图只能支持已确认的空间结构、明显元素、材质、尺度感、色彩和基础光影。用户选图不代表接受其中全部偶然内容。图片中新出现的门窗、家具、灯具、人物或道具，必须先经视觉分析列出并由用户确认；否则不得写入下一条提示词。

反方向视角只有 `CONTENT_REFERENCE` 而没有 `LAYOUT_REFERENCE` 时，把结果定位为“同一场地的候选反方向设计”，不得声称精确还原未展示区域；具备已确认布局参考时，才按布局事实编译反方向关系。

## 5. 摄影属性

所有正式提示词必须选择与用途匹配的摄影属性，不留空，也不编造精确毫米焦距：

- **图像用途**：主建立图优先写“影视美术场地参考图”；只做气氛探索时写“剧情场地气氛图”。
- **摄影机高度**：默认成人视平线；只有空间或叙事需要时使用低机位、俯视或鸟瞰。
- **视野**：场地建立优先适度广角；标准视野用于更自然的空间感；空间压缩只在明确需要时使用。
- **透视**：空间参考图默认自然直线透视，避免鱼眼和夸张边缘拉伸。
- **垂直线**：建筑和室内场地图默认保持端正；明确的倾斜构图除外。
- **景深**：空间参考优先中等至深景深，确保门窗、通道和固定元素可读；浅景深只用于气氛图。

## 6. 视觉锚点压缩

后台任务包和 `storyboard_locations.md` 保留全部事实；最终提示词不得逐项抄写。编译前把信息分成：

1. **硬锚点**：一旦漂移会破坏空间身份或连续性的3–5项事实。
2. **软描述**：材质、使用痕迹、色彩、情绪和次要环境信息。
3. **风险限制**：当前任务最可能发生的3–5项错误。

硬锚点按优先级进入提示词，通常包括核心门窗关系、主活动区、关键固定家具、主要通道和动机光入口。超过5项时，合并同类关系或请用户排序；不得把完整场地档案压成一条超长列表。

只写当前机位真正可见或决定空间理解的内容。画面外但必须保持的事实留在后台档案，不强塞进提示词。软描述选择2–4项最有辨识度的可见特征；风险限制只保留与当前任务直接相关的内容。

## 7. 编译规则

按以下顺序组织提示词：

```text
场地身份与功能
→ 时代与地域
→ 图像用途、摄影机高度、视野、透视与景深
→ 当前视角和3–5个硬锚点
→ 2–4项核心材质与环境特征
→ 动机光源、明暗、阴影、冷暖与曝光
→ 剧情情绪与电影质感
→ 空间可读性
→ 3–5项高风险限制
→ 画幅
```

使用能被看见的空间与光影语言，不写“布局合理”“氛围高级”“神秘光”“电影感拉满”等空泛词。先正向描述目标画面，再补充少量与当前任务直接相关的禁止项；不得在末尾堆叠几十个否定词。

光源必须对应已经确认的窗户、门口、顶灯、台灯、路灯、月光、阳光或屏幕等来源。不得凭空添加轮廓光、彩光、烟雾或可见灯具。电影质感不能牺牲门窗、通道、固定元素和空间纵深的可读性。

只写最终目标画面，不写“旋转图片”“把图片改成夜晚”“保持所有东西不变”等编辑指令。即使使用参考图，也要重新完整描述目标视角。

目标接口为 LibTV 时，不输出 `--ar`、`--no`、`--raw`、`--s`、`--v`、`--iw`、`--sref` 等参数，画幅写入提示词正文。只有用户明确要求原生 Midjourney 格式时，才根据用户当前要求附加参数；不得凭经验自动推荐版本或数值。

## 8. 提示词骨架

骨架只用于内部编译，删除空字段后输出，不得保留方括号。

### MAIN_VIEW

```text
[时代与地域]的[场地身份]，[图像用途]。摄影机位于[位置]，采用[高度]、[视野]、[透视]、[景深]，[垂直线要求]，朝向[观察方向]。[按优先级描述3–5个硬锚点及其画面关系]。[2–4项核心材质、使用痕迹与环境特征]。[动机光源]从[方向]进入，[明区、暗区、阴影与曝光重点]，形成[具体可见的色彩、质感和情绪]。保持门窗、通道、固定元素和空间纵深清晰可读。[3–5项当前高风险限制]。横向16:9电影画幅。
```

### REVERSE_VIEW

```text
以[主建立图名称，CONTENT_REFERENCE]和[布局图名称，LAYOUT_REFERENCE；如无则注明候选设计]为依据，生成同一处[时代与地域][场地身份]的对向建立视角，[图像用途]。摄影机位于[新位置]，采用[高度]、[视野]、[透视]、[景深]，朝向[新方向]。[按新机位关系描述3–5个硬锚点]。[核心材质与环境特征]保持一致。[动机光源]仍位于同一空间位置，从当前机位呈现[明暗、阴影与曝光关系]。[3–5项当前高风险限制]。横向16:9电影画幅。
```

### LIGHTING_VARIANT

```text
以[基础场地图名称，CONTENT_REFERENCE]为依据，保持[场地身份]及当前摄影机高度、视野、透视、景深和构图关系，只把场地从[原光影状态]转换为[目标光影状态]。[列出3–5个必须保持的硬锚点]。[目标动机光源]从[方向]作用于空间，[主要明区、暗区、阴影、曝光与冷暖关系]，形成[具体情绪]。只改变已确认的时间、天气或光源状态，[3–5项当前高风险限制]。横向16:9电影画幅。
```

## 9. 输出与暂停格式

正式输出：

```markdown
## Midjourney 场地图提示词

- 任务类型：
- 场地：
- 参考需求：
- 参考图：图片名称｜CONTENT_REFERENCE / STYLE_REFERENCE / LAYOUT_REFERENCE｜允许提供的信息

### 提示词

[一条完整中文提示词]
```

用户确认提示词后必须保存；未确认版本只在对话中展示，不写入锁定记录。文件名：

- `location_场地名_main_view_prompt.md`
- `location_场地名_reverse_view_prompt.md`
- `location_场地名_lighting_版本名_prompt.md`

场地名和版本名先用 [`safe_names.py`](../scripts/safe_names.py) 安全化，保留中文但移除路径含义和跨平台非法字符。新文件同名时追加稳定编号，不自动覆盖。无论是否同时更新 `storyboard_locations.md`，都准备候选文件并传入统一场次标签，使用 [`project_transaction.py`](../scripts/project_transaction.py) 作为一个事务提交；独立入口同样使用本机资产库中的项目目录。

缺少关键事实时输出：

```markdown
## Midjourney 编译暂停

- 任务类型：
- 缺失字段：
- 对提示词的影响：
- 需要用户确认或补充：
```

## 10. 自检

输出前检查：

- 任务类型、参考需求、每张图的参考类型和权限是否正确；
- 是否把氛围图误作空间事实，或把平面图误作材质和光影事实；
- 是否根据用途填写摄影机高度、视野、透视、垂直线和景深；
- 是否只保留3–5个硬锚点、2–4项软描述和3–5项高风险限制；
- 是否只使用已确认事实，未知区域是否仍为未知；
- 当前左中右、前中后景和摄影机方向是否明确；
- 反方向是否仍为同一空间且没有机械镜像；
- 光影是否来自场景灯光卡和真实动机光源；
- 光影版本是否只改变允许变化项；
- 是否兼顾电影质感与空间参考价值；
- 是否没有剧情人物、随机装饰、无来源光影和空间漂移；
- 是否只输出一版中文提示词及明确参考图说明；
- LibTV模式是否没有参数、JSON、其他提示词系统或直接出图行为；
- 是否在正文写明当前画幅。

## 11. 场地档案与保存

整个项目只维护一份 `storyboard_locations.md`：

“整个项目”指资产库中当前项目 ID 对应的目录；不同项目不得串用场地档案。档案按逻辑名定位到隐藏记忆目录，不在网页展示为资产卡。

```markdown
## 场地 LOC-01｜场地名

- 适用场次：
- 场地功能：
- 锁定状态：待确认 / 已锁定 / 待复核
- 结构与门窗：
- 固定家具与明显元素：
- 人物活动区与通道：
- 材质与环境状态：
- 场地基础光影：
- 摄影基线：图像用途、摄影机高度、视野、透视、垂直线、景深
- 不可漂移空间锚点：按优先级排列
- 禁止出现：
- 未知区域：

### 图片资产
| 图片编号 | 视角 | 参考类型 | 允许提供的信息 | 文件路径或明确标识 | 事实卡状态 | 用户选定状态 |
|----------|------|----------|------------------|--------------------|--------------|--------------|

### 提示词记录
| 任务类型 | 提示词文件 | 参考图及类型 | 确认状态 | 对应图片 |
|----------|------------|--------------|----------|----------|
```

用户返回选定图片后，先按视觉分析规范生成事实差异：保持项、新增项、冲突项和未知项。只有用户确认的项目写入锁定事实。开始新会话时先读取场地档案中的锁定状态、图片资产和提示词记录。
