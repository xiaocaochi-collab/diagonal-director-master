# 本机导演资产库

本模块管理项目、文件夹和文件。它不引入资产卡，不把模型工作卡展示为产品内容，不改变五步流程、确认权限、镜头事实源或素材锁定规则。支持 Windows、macOS、Linux 的 Python 3.10+，仅用标准库；不要求安装 Node、数据库服务或联网。

## 1. 所有会话的共同入口

每台电脑维护自己的资产库，各电脑不自动同步。默认根目录为当前使用者的 `~/Documents/Codex/DIAGONAL资产库/`，由脚本在运行时解析，绝不能写入作者的用户名或机器路径。可用环境变量 `DIAGONAL_ASSET_HOME` 或 `--root` 指定其他本机位置；已登记项目的 `.diagonal_project.json` 记住它所在的库。不要把库放在 skill 安装目录、聊天临时目录或代码缓存里。

首次执行任一创作入口前，运行 `python3 <skill>/scripts/asset_library.py projects`，从已有项目与用户上下文确定项目。用户明确项目后直接复用；有多个同名或不清楚归属时，只问项目归属，不误建新项目。用户要求新项目时运行 `create --title 项目名称`；标题不足以确定时询问名称。告知项目实际路径即可，默认资产库位置不额外增加审批节点。当前宿主有文件系统权限要求时按宿主处理。

- `create`：在资产库下建立新项目，返回项目 ID、绝对路径。
- `attach --project 绝对路径 --title 名称`：登记用户明确指定的空目录或已有新版目录，不移动文件。对已有旧版平铺项目，先按“旧项目”一节处理。
- `projects`：列出项目。
- `resolve --project 项目路径 --name 逻辑文件名 [--scene 第01场_客厅]`：查找正式文件路径。
- `list --project-id ID [--query 关键词] [--history]`：查询已登记成果及历史快照；这是模型辅助索引，不是网页资产卡。

所有命令以 `python3 <skill>/scripts/asset_library.py` 为前缀，Windows 可用 `py -3`。`--root` 放在子命令之前。查读特定项目时优先使用项目绑定的库；独立 MJ 也登记为项目，不启动剧本分析流程。

## 2. 用户看到的结构

```text
项目/
├── 正式分镜/
│   ├── 第01场_客厅/
│   ├── 第02场_街道/
│   └── 全片/
├── 提示词/
│   ├── 第01场_客厅/
│   ├── 第02场_街道/
│   └── 跨场共用_客厅/
├── 人物资产/人物名/（按需增加造型或场次子目录）
├── 场景资产/场景名/（按需增加视角或场次子目录）
├── 道具资产/道具名/
└── 其他成果/全片或对应场次/
```

六个分类自动创建。场次文件夹按实际输出创建，不预填虚构场次。场次标签在同一项目统一，例如 `第01场_客厅`；同一场分镜与提示词使用相同标签。跨场复用的人物、场景、道具按名称组织，不为每场复制素材。全片分析、情绪曲线 PNG、统计等交付物进入其他成果。纯后期场次的既有分镜排除规则不变。

用户在网页上传图片、视频等素材。上传本身不等于用户确认图片中的全部剧情、空间或光影事实；只有创作任务确需用图时才按既有视觉分析和确认流程处理。Skill 不自动生成、替换或删掉上传素材，不把上传变成新的确认表单。

## 3. 模型记忆与唯一正式文件

`storyboard_scene_cards.md`、`storyboard_continuity.md`、`storyboard_locations.md` 放入项目 `.diagonal_memory/`。所有点号开头的状态、映射、快照、事务、回收记录均在网页隐藏且不可通过文件接口访问。

其他模块所写的 `storyboard_第X场_场景名.md` 等均是**逻辑文件名**。实际读写先用 `resolve` 获取路径。`.diagonal_paths.json` 仅保存逻辑名到实际文件的映射；网页移动或重命名后也通过它定位。它不保存导演事实。

第③、④步的未定稿预览继续只在对话中处理，不出现在正式分镜文件夹，也不为资产库新增“资产卡”“候选卡”或重复正式分镜。全片分析仍只有一份正式文件；网页打开的正式文件就是事实源，没有“网页副本”与“模型副本”。

续作读取项目绑定、路径映射、事务状态和 `.diagonal_user_changes.jsonl`（若有），然后按原工作流读取必要事实源。网页编辑或删除正式内容后，依据变更记录和当前内容判断影响，必要时标记相关分镜／连续性待复核；不能把网页手工编辑自动说成已经通过导演自检。也不得擅自恢复成旧版本。只处理尚未处理的变更，已处理到的日志位置在现有项目工作记忆中记录。

## 4. Skill 输出自动归档

正式分镜第⑤步、提示词获得原流程所需确认后，以及其他已确认成果输出时，统一调用 `project_transaction.py apply`。即使只写一份提示词或曲线图，也用同一入口。不要直接向正式文件夹写文件。

写入清单仍采用原结构，新增场次标签、可选登记元数据和覆盖校验：

```json
{
  "writes": [
    {
      "target": "storyboard_第1场_客厅.md",
      "source": "候选文件绝对路径",
      "scene": "第01场_客厅",
      "replace_existing": false,
      "asset_metadata": {"status": "final", "kind": "分镜"}
    },
    {
      "target": "第1场提示词.md",
      "source": "候选文件绝对路径",
      "scene": "第01场_客厅",
      "replace_existing": false,
      "asset_metadata": {"status": "confirmed", "kind": "Seedance提示词"}
    }
  ]
}
```

这是格式示例，不要求把不同确认节点的分镜与提示词放进同一个事务。同一确认节点涉及的相关文件才统一提交。

- `target` 仍传逻辑文件名，不手工把整个路径塞入文件名；脚本自动放入类别／场次，并返回真实路径。更新时自动遵循路径映射。
- 提示词必须传 `scene`；独立场地或跨场提示词使用 `跨场共用_场地名`。正式分镜也应显式传同一场次标签。
- 覆盖已存在的文件时，必须先读它并计算 SHA-256，在清单中传 `expected_sha256` 与 `replace_existing: true`；其他会话修改后摘要不符就停止，重新读取，不能用最新摘要硬盖过未知改动。
- 原先不允许覆盖的节点继续遵守原确认边界。自动归档不等于获得重新生成或覆盖人工修改的权限。
- `status` 区分 `recorded`、`confirmed`、`final`、`needs_review`。工作记忆默认 recorded，不把整份记录误说成全部用户确认。
- 脚本使用项目写锁、文件事务与隐藏快照；并发会话不得绕过它。元数据登记失败会留下 `asset_sync: pending`，先执行原事务 `recover --mode auto` 补齐，成功后才报告“归档完成”。
- 更新情绪曲线时先渲染到暂存位置，再连同所依据的全局分析提交；不要直接覆盖正式 PNG。
- 网页只读展示与文件管理不要求启动完整分镜流程。

## 5. 打开本地网页

运行：

```text
python3 <skill>/scripts/asset_server.py start --open
```

在 Codex 中可不带 `--open`，取得返回的 URL 后用宿主浏览器工具打开。服务只绑定 `127.0.0.1`，自动选择可用端口并复用本库正在运行的服务。每次通过启动器取得地址，不假定永久端口。项目数据不上传到外部服务。

网页提供：项目创建、项目回收与恢复、六类文件夹、子文件夹、名称搜索、网格／列表、图片预览、视频首帧与播放、音频播放、文本查看／复制／修改、下载、批量上传和拖放、重命名、移动、文件回收与恢复，以及磨砂黑白外观切换。同名上传追加编号，文本保存检查版本并保留旧快照，可在“历史版本”中下载；原有上传素材保留在项目文件夹，用户移动或删除时网页同步更新路径。上传单文件上限 4 GB；文本编辑上限 4 MB；媒体首帧和播放取决于浏览器编码支持，不支持时显示图标并可下载原文件。视频支持范围请求和拖动进度。

项目从网页移除时须输入项目名称确认。网页创建在资产库内的项目连同原文件夹移入隐藏的项目回收站，可在网页恢复；外部接入的项目只从列表移除，原目录与文件保留在原位置，恢复后重新显示。项目回收不会抹掉项目历史快照。不要把“移到项目回收站”表述成永久清除文件。

目录以文件系统为准，外部修改后刷新网页即可看到。用户上传的素材可在对应分类文件夹按文件名查找；模型辅助索引 `list` 仅登记 Skill 输出与网页编辑版本，不要求上传素材拥有资产卡。网页搜索按名称及目录，不宣称支持图片语义检索或全文搜索。内部记忆没有产品页面。

## 6. 旧项目与分发

不要自动扫描使用者整台电脑或搬动旧项目。用户指定需要接入的旧项目时，先读取现有事实源、目录和事务状态，恢复未完成事务。推荐建立一个新资产库项目，再把明确属于该项目的已有成果按上述事务归档、工作记忆放入隐藏目录，并同步项目头中的新目录；原目录保留。只有用户明确选择原地整理时才迁移原文件，并保存路径映射；不得直接 attach 后留下两份互相竞争的正式文件。

新版已有项目直接用其项目绑定续作。跨电脑复制一个完整库时需重新登记本机路径，不能复用另一台机器的绝对路径；本版本不做云同步。

分发包包含 Skill、references、scripts、assets、agents、测试、启动文件和必要的使用说明、依赖清单与仓库忽略规则；不能包含个人资产库、项目文件、数据库、日志、历史快照、运行中的服务信息或本机配置。使用者安装后由自己的 Codex 初始化自己的库。无需另外部署网站；macOS 可双击 `打开资产库.command`，Windows 可双击 `打开资产库.cmd`，或直接请 Codex 打开。服务关闭后再次运行启动命令，已有文件和项目仍保留。
