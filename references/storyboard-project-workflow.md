# Storyboard 项目级工作流

本文件承接完整分镜项目的项目级规则：总流程、全片基线、情绪曲线、连续性总系统、剧情时间、光影圣经、场景图、MJ/Seedance 项目内接入与开始前确认。只有进入 `STORYBOARD_PROJECT` 时完整加载；单独 MJ 或 Seedance 请求不加载本文件。

本文涉及的逻辑文件名先按本机资产库的 `resolve` 定位；项目输出通过统一事务归档，内部工作卡在隐藏目录。

## 总流程

1. 使用文档能力读取标准剧本 `.docx`。
2. 建立场次、人物、关键物品、剧情时间和人物状态基线；识别含实质性身体对抗的场次。
3. 确认类型、基调、全片情绪曲线和全片光影圣经；存在武戏时按 [武戏导演系统](action-director-system.md) 确认项目动作风格与能力边界。
4. 可选：使用宿主模型原生视觉能力分析场景图。
5. 可选且仅在用户明确要求时：生成 Midjourney 场地图提示词。
6. 按场次顺序逐场执行固定五步流程；每场在第①步提供正常／工业模式选择，按 `storyboard-scene-workflow.md` 执行。镜头时长与场次容量按 `duration-capacity-system.md` 在第②、③、⑤步持续校验。
7. 全部场次完成后执行跨场一致性检查、合并分镜，并生成统计与连续性文件。

**铁律：一场完成五步并定稿后，才能进入下一场。**

## 权威关系

本模块服从主入口的规则优先级和核心边界，不反向加载主入口，也不在此建立第二套冲突裁决。

## 项目事务与中断恢复

正式项目文件使用 [`project_transaction.py`](../scripts/project_transaction.py) 统一提交。它只维护技术状态，不承担导演事实源：

1. 在项目目录外或项目隐藏暂存区准备本轮全部候选文件；生成文件名时先用 [`safe_names.py`](../scripts/safe_names.py) 安全化场景名、地点名和版本名。
2. 提交前读取 `.storyboard_project_state.json`。若存在未完成事务，暂停新写入并先执行 `recover --mode auto`；能校验完整暂存文件时继续完成提交，否则用备份回滚。
3. 把同一导演确认或工业模式授权定稿节点涉及的正式分镜、工作卡、连续性文件和项目头作为一个写入清单提交。脚本先暂存、计算 SHA-256、备份会被覆盖的旧文件，再逐项原子替换；每替换一项即更新事务状态。
4. 提交完成后再次核对清单摘要。只有全部目标文件与清单一致，才能向用户报告“已定稿”或进入下一场。
5. `.storyboard_backups/` 保留本次覆盖前版本用于恢复；`.storyboard_transactions/` 保存尚未完成的暂存内容。不要把这些隐藏技术目录合并进正式分镜或交付统计。

写入清单 JSON 使用：

```json
{
  "writes": [
    {"target": "storyboard_第1场_客厅.md", "source": "候选文件绝对路径", "replace_existing": false},
    {"target": "storyboard_scene_cards.md", "source": "候选文件绝对路径", "replace_existing": true}
  ]
}
```

普通新成果默认不覆盖同名文件，可追加稳定编号；正式单场分镜、完整版、全局分析、工作卡、连续性、场地档案、统计与情绪曲线等唯一事实源同名时停止，核对既有文件后才能使用 `replace_existing: true` 和预期摘要更新。已登记的文件若被网页或外部操作删除，也须先复核删除意图，不得静默重建。脚本退出失败、状态摘要不一致或恢复仍失败时停止，不得继续写下一场。

## 第0步：建立全片基线

分析全片叙事信息如何呈现、观众视点与镜头视觉策略时，先读 [`shot-narration-viewpoint.md`](shot-narration-viewpoint.md)；设计全片摄影造型或光影圣经时，先读 [`cinematography-lighting-knowledge.md`](cinematography-lighting-knowledge.md) 和适用的 [`lighting-system.md`](lighting-system.md)。这些知识只为既有全片分析提供依据，不增加项目事实文件或确认轮次。

### 场次、人物和关键物品

建立：

- **场次清单**：场次号、场景标头、出场人物、场次概要。纯黑屏字幕和纯后期场次标记为「后期」，维持现有规则，不进入分镜流程。
- **人物清单**：统一每个人物的标准称呼，后续不得混用代称。
- **关键物品清单**：记录反复出现或影响剧情的物品、初始位置、归属和状态。
- **类型与基调**：展示判断依据并请用户确认。

### 全片情绪曲线

在完整阅读剧本后，按场次分析观众体验的主导情绪与强度变化。情绪曲线是叙事分析，不等同于人物当下表情，也不等同于光影明暗。

使用五级定性强度：`1 极低 / 2 偏低 / 3 中等 / 4 偏高 / 5 峰值`。等级只用于比较全片相对起伏，不宣称精确测量。

```markdown
## 全片情绪曲线

### 总体走向
- 起始状态：
- 主要累积方式：
- 全片峰值：
- 释放或余波：
- 关键转折：

### 逐场曲线
| 场次 | 主导情绪 | 入场强度 | 场内峰值 | 离场强度 | 走势 | 触发事件 | 叙事功能 |
|------|----------|----------|----------|----------|------|----------|----------|

### 曲线诊断
- 重复或停滞区段：
- 强度跳变但依据不足：
- 高潮前的累积是否充分：
- 高潮后的释放是否成立：
- 需要用户裁决：
```

`走势` 使用：上升 / 下降 / 持平 / 波动 / 急转。每个强度和转折必须能指向具体剧情事件；不得为了制造漂亮曲线而改写剧情。先展示曲线与诊断，用户确认后锁定。剧本或场次结构改变时，只重算受影响场次及其下游关系。

将类型与基调、全片情绪曲线、全片光影圣经统一保存到 `storyboard_global_analysis.md`；存在武戏时把已确认的“动作风格与能力边界”写入同一文件，不另建全局事实源。

#### 情绪曲线图片

用户确认全片情绪曲线后，运行 [`render_emotion_curve.py`](../scripts/render_emotion_curve.py)，从 `storyboard_global_analysis.md` 已确认的“逐场曲线”表直接生成 `storyboard_emotion_curve.png`。

- Markdown表是唯一事实源，PNG只是其可视化，不重新分析剧情。
- 横轴按场次依次绘制入场、场内峰值和离场节点；纵轴固定为1—5级。
- 图片标出场次边界、强度节点、全片峰值与主导情绪。先生成到暂存路径，再通过统一事务归档到其他成果／全片。
- 修改已确认曲线、场次结构或相关下游强度后，必须重新生成PNG，并在核对旧图摘要后通过统一事务更新。
- 绘图失败时保留Markdown数据并说明原因，不得用生成式图片代替数据图。
- PNG 的底部品牌署名按 [品牌与成果署名](brand-presentation.md) 处理；用户要求无署名图时使用 `--no-branding`，不改变曲线数据。

### 连续性总系统

先完整加载 [`story-time-continuity-system.md`](story-time-continuity-system.md)。需要建立或修改服装状态时再加载 [`costume-system.md`](costume-system.md)；需要建立或修改妆发、人物生理外观或特殊效果时再加载 [`makeup-hair-system.md`](makeup-hair-system.md)。不要在第0步无条件同时加载全部专业细则。

整个项目只维护一份 `storyboard_continuity.md`。剧情时间、关键物品、服装、妆发、特殊效果以及固定光源的剧情运行状态全部写入该文件；不得为各专业系统另建互相重复的项目状态文件。场景灯光卡仍是光影设计的唯一事实源，总表只记录开关、损坏、移动等会跨镜或跨场继承的剧情状态。

另维护一份 `storyboard_scene_cards.md` 作为本地工作记忆，保存正常模式经用户逐步确认的内容，以及工业模式在第①步由用户选择时接受的分析、第⑤步依授权定稿的简稿：每场处理状态、执行模式、场景分析、场景灯光卡、光影叙事曲线、人物状态与连续性确认卡，以及分镜简稿。工业模式的自动设计须标明“工业模式授权定稿”，不得写成“用户逐镜确认”。第③、④步候选内容不得提前写入该文件；第⑤步记录定稿状态，工业模式还须写入内部通过的简稿及必要的第①步授权修订，不复制完整正式分镜。

续作时读取项目头、当前场对应工作卡和所需连续性状态，不依赖聊天记忆，也不重复载入全部场次工作卡。

续作时先检查 `.storyboard_project_state.json` 是否存在未完成事务并按本模块恢复，再读取正式事实源。若输出目录已存在 `storyboard_continuity.md`，先读取其项目头、完成进度和待复核项；同时读取已有的 `storyboard_global_analysis.md`；只要 `storyboard_locations.md` 存在就读取。然后对照当前剧本文件确认是否续作。不得仅凭聊天记忆判断进度，也不得自动覆盖旧版本。

若存在 `storyboard_scene_cards.md`，同时读取当前处理场次的工作卡；没有该文件时按上述结构建立。不得用临时单场草稿文件代替工作卡。此处的自动建立只适用于完整分镜流程；独立进入 `SEEDANCE_IN_PROJECT` 时不得新建或补写工作卡、连续性总表或正式分镜，缺失资料按 Seedance 模块的入口规则处理。

采用三层状态结构：

```text
全片连续性总表
→ 当前场开始状态快照
→ 逐镜只记录变化
```

### 剧情时间表

不要把剧本文件顺序自动视为故事时间顺序。逐场建立：

```markdown
| 场次 | 时间线 | 故事日 | 时段 | 前置剧情场次 | 时间关系 | 连续性组 |
|------|--------|--------|------|--------------|----------|----------|
```

规则：

- `前置剧情场次` 是本场在故事时间上真正承接的场次，不默认等于编号相邻的上一场。
- `时间关系` 使用：顺接 / 时间省略 / 时间跳跃 / 平行发生 / 回忆 / 梦境 / 无法确认。
- 只有顺接或明确连续的场次，才直接继承人物、关键物品和固定光源运行状态。
- 回忆、梦境和平行线分别建立连续性链，不与当前时间线串联。
- 无法判断时向用户确认，不得按场次号猜测。

同时在 `storyboard_continuity.md` 建立连续性组、人物基础状态索引，并依据服装和妆发规范提出首次出现的人物状态方案。服装方案需用户确认后锁定；妆发方案由 Skill 主动提出并在合并确认中确认。伤口、血迹、汗水、泪水、雨水和污渍没有剧情、动作或环境依据时不得主动增加。

### 全片光影圣经

生成或修订任何光影内容前，完整加载 [`lighting-system.md`](lighting-system.md)。建立并请用户确认：

```markdown
## 全片光影圣经

- 总体影调：
- 基础冷暖关系：
- 人物面部受光原则：
- 阴影原则：
- 曝光优先级：
- 全片光影变化曲线：
- 禁用方式：
```

只使用定性电影语言。没有明确资料时，不编造照度、功率、精确色温、精确光比、入射角或曝光参数。

### 场景图视觉分析（可选）

用户提供场景照片、平面图、走位图、灯光图、机位图或氛围参考图时，完整加载 [`vision-prompt.md`](vision-prompt.md)，直接使用当前宿主环境的原生视觉理解能力分析，不依赖额外配置、指定模型或分析脚本。

输出并分开存储：

1. **空间测绘报告**：可见空间结构、固定装置、家具、通行区和自然站位点。
2. **光影证据报告**：可见光源、自然光入口、受光区、阴影、冷暖倾向和未知项。
3. **人物与机位参考报告**：图片明确展示的人物位置、走位、摄影机位置和观察方向。

事实边界：

- 单张透视图没有展示的墙面、画外空间和真实方位标记为未知。
- 仅在存在可靠尺度参照时给出范围估计；不得为满足表格而编造数字。
- 平面图、走位图和机位图中未明确标注的颜色、箭头、阴影不得解释为光源。
- 氛围参考图只影响风格倾向，不作为空间、人物站位或灯位事实。
- 图片结论标记为：已确认 / 合理推断 / 未知。用户修正立即锁定，后续不得覆盖。

将结果映射为每场的空间参照表与光影证据表。空间参照表记录固定光源的存在和位置；是否开启及如何使用由场景灯光卡决定。

只要场景图分析产生并经用户确认锁定的正式空间或场地事实，就建立或更新 `storyboard_locations.md`；不以是否使用 Midjourney 为前提。

图片无法读取或无法判断类型时，报告原因并继续其他图片或纯文本流程。

### Midjourney 场地图提示词（按需）

只有用户明确要求“生成MJ场地图提示词”“生成主建立图提示词”“生成反方向视角提示词”或“生成场地光影版本提示词”时，才完整加载 [`midjourney-location-prompt-system.md`](midjourney-location-prompt-system.md)。不得在普通分镜流程中自动生成。

所有场地事实、未知区域、提示词版本和已选图片统一写入 `storyboard_locations.md`。没有该文件时按MJ规范建立；不得把场地结构塞进 `storyboard_continuity.md`。

调用前先从场地档案、空间参照表、相关光影资料和用户指定参考图构造任务包。纯文本资料不足时，主系统可以根据场地功能提出一版功能性空间方案，但必须标记为“待确认”；用户确认并写入场地档案后，MJ模块才能正式编译。后台事实保持完整，最终提示词只选择3–5个不可漂移空间锚点，并补充摄影机高度、视野、透视、景深和图像用途。参考图必须分别标注为内容参考、风格参考或布局参考，不得混用权限。

支持：

- `MAIN_VIEW`：首次生成主建立视角，默认无场地图参考图；
- `REVERSE_VIEW`：基于用户选定并确认的主建立图生成反方向视角；
- `LIGHTING_VARIANT`：保持同一视角与空间不变，只改变已确认的时间、天气或光源状态。

主建立视角使用场地基础光影，不要求先完成某一场的灯光卡；特定场次的光影版本必须等该场灯光卡确认后生成。每项任务只输出一版中文提示词和明确的参考图说明，不输出其他图像或视频提示词系统。用户返回选定场地图后，按场景图视觉分析规则提取证据；图片中的偶然新增元素必须经用户确认后才能成为锁定事实。

用户仅把场地图用于气氛参考时，MJ流程不阻塞分镜。用户声明场地图是正式空间依据时，在选图和空间事实确认前，相关场次不得进入正式分镜。若分镜已经定稿，后来选定的场地图不得反向覆盖分镜，只报告冲突并等待裁决。

### Seedance 2.0 视频提示词（按需）

只有用户明确要求生成 Seedance 2.0 提示词时，才完整加载 [`seedance-prompt-system.md`](seedance-prompt-system.md)、[`seedance-optics-system.md`](seedance-optics-system.md) 和 [`duration-capacity-system.md`](duration-capacity-system.md)；本场包含可见人物表演时同时加载 [`acting-director-system.md`](acting-director-system.md)。仅以第⑤步已定稿分镜为镜头事实源，并读取已确认的全局分析、当前场工作卡、必要连续性与场地资料；按场生成一条完整中文提示词，不自动拆段，不增删、合并、拆分、重排或改写正式镜头和剧本对白。先确认技术风格、逐镜对角视场角、摄影机物理距离、可见光学结果、剪辑与持续性物理变化，再输出独立的 `第X场提示词.md`。旧项目没有“人物表演导演”区块时，只编译正式分镜已经明确写出的可见或可听表演，不反推目标、策略、潜台词或新增反应，也不因此返回第①步或改写工作卡。Seedance 独立入口缺少正式分镜之外的辅助资料，且正式分镜不足以唯一确定所需内容时，一次性列出缺口并暂停；不得自动创建项目状态文件。提示词是派生成品，不覆盖正式分镜，也不把用户后续人工修改自动回写项目状态；同名文件已存在时不得自动覆盖。

### 开始前确认

进入第1场前，确认：

- 场次、人物标准称呼和关键物品；
- 剧情时间表和连续性组；
- 人物基础服装、妆发与特殊状态；
- 类型与基调；
- 有实质性武戏时的项目动作风格与能力边界；
- 全片情绪曲线；
- 全片光影圣经；
- 输出目录与文件命名；
- 场景图及其场次对应关系（如有）；
- 用户已经明确指定的全片/场次目标时长或生成段容量及其适用范围（如有）。未指定时不自行设定平台上限。

用户未指定输出目录时，使用已定位的本机资产库项目目录并告知绝对路径，不增加目录确认轮次；项目归属不明确时先确认项目。用户明确指定其他目录时登记该目录并沿用。不得写入聊天软件缓存目录、附件临时目录或系统临时目录。场景名、地点名和版本名进入文件名之前必须由 [`safe_names.py`](../scripts/safe_names.py) 安全化；不得把用户文本直接当作路径。
