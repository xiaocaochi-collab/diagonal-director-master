# 化妆与发型系统

本系统负责妆容、发型、人物生理外观和特殊效果状态的设计与连续性。项目状态统一写入 `storyboard_continuity.md`。

## 1. 设计权限

- 可以根据人物身份、剧情时间、刚经历的动作、天气和环境主动提出一版妆发方案。
- 新的基础妆发状态第一次出现时进入每场第①步合并确认；正常模式经用户确认后锁定，工业模式依本场明确选择接受已展示方案，并可在授权范围内修订，来源须标明。依据不足的关键方案仍须暂停询问。
- 不输出品牌、色号、详细化妆步骤或与剧情无关的装饰性设计。
- 汗水、泪水、血迹、伤口、泥污等没有剧本、动作或环境依据时不得主动增加。

## 2. 妆发编号

基础妆发使用：`人物-M01`、`人物-M02`。

只有基础造型真正改变时创建新编号。散乱、湿润、出汗或流泪属于同一编号下的状态变化。

```markdown
| 妆发编号 | 人物 | 状态用途 | 首次场次 | 适用连续性组 | 初始状态 | 锁定状态 |
|----------|------|----------|----------|--------------|----------|----------|
```

## 3. 基础妆容和人物状态

允许设计和追踪：

- 妆容强度：无明显妆感 / 自然 / 明确造型需要。
- 精神状态：正常 / 轻度疲惫 / 明显疲惫。
- 面色：正常 / 苍白 / 潮红 / 病态；必须有依据。
- 醉酒、失温、高热等可见状态；必须有剧情依据。
- 汗水、泪水、雨水、灰尘和泥污。

## 4. 发型状态

- 整齐 / 轻微散乱 / 明显散乱。
- 干燥 / 潮湿 / 湿透。
- 被风吹动 / 被动作破坏 / 被重新整理。
- 遮挡面部 / 离开面部。
- 状态未知。

变化必须由睡眠、奔跑、打斗、风雨、戴帽、脱帽、主动整理或时间跳跃等原因触发，不得在切镜时自动恢复。

## 5. 特殊效果状态

特殊状态使用：`人物-S01`、`人物-S02`。

包括：伤口、血迹、瘀青、擦伤、烧伤、肿胀、泥污、病态和衰老效果。

归属边界：头发与面部普通状态归妆发；身体伤口和身体血迹归特殊效果；衣物上的血迹、雨水和污渍归服装。同一事件可以同时触发多个系统，但每条记录必须写明具体承载部位，不得用一个模糊状态代替全部变化。

```markdown
| 状态编号 | 人物 | 类型 | 身体位置 | 左右侧 | 伤情阶段或演化状态 | 首次镜头 | 当前状态 | 后续继承 |
|----------|------|------|----------|--------|--------------------|----------|----------|----------|
```

### 伤情阶段

只对伤口、擦伤、烧伤等具有受伤与处理过程的状态使用阶段：

- 阶段0：尚未发生。
- 阶段1：刚发生。
- 阶段2：持续活动中。
- 阶段3：已经初步处理。
- 阶段4：恢复中。
- 阶段5：已恢复。

伤情阶段变化必须有时间、处理动作、剧情事实或用户确认作为依据。衣物或皮肤表面的血迹、泥污不使用伤情阶段；瘀青按出现、发展、消退记录；病态和衰老按剧情指定的当前外观记录。

## 6. 可变量级

泪水、汗水、雨水、泥污和血迹使用定性等级；记录时必须同时注明承载部位：

- 0：无。
- 1：轻微。
- 2：明显。
- 3：严重。

例如：`双眼泪水 0→1`、`擦拭左脸后泪水 2→1`。不编造精确面积和液体数量。等级只表示当前可见量，不代表伤情阶段；活动性出血另写“活动性=是/否”。

## 7. 可见性规则

状态写入正式分镜前依次判断：

1. 状态确实存在；
2. 相关人物和身体部位入镜；
3. 角度与遮挡允许看见；
4. 景别足够；
5. 场景灯光卡与逐镜受光允许辨认；
6. 状态承担叙事功能或发生可见变化。

不得为了展示妆发、伤口或血迹而修改景别、机位、人物角度、灯光或曝光。

## 8. 连续性检查

- 发型是否无理由恢复整齐或干燥。
- 汗水、泪水、雨水、灰尘和泥污是否错误消失。
- 伤口与血迹的位置、左右侧、阶段和严重度是否一致。
- 擦拭、清洗、包扎和治疗后是否正确更新状态。
- 时间跳跃是否足以支持恢复或重置。
- 同一动作覆盖是否使用相同时间点的可见状态。
