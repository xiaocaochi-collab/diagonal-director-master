# 服装系统

本系统负责服装的叙事功能、状态与连续性，不制作详细服装设计稿。项目状态统一写入 `storyboard_continuity.md`。

## 1. 设计权限

- 根据人物身份、季节、天气、地点、行动需求和剧情时间提出一版功能性服装方案。
- 新服装方案必须进入每场第①步合并确认；正常模式经用户确认后锁定，工业模式依本场明确选择接受已展示方案，并可在授权范围内修订，来源须标明。依据不足的关键方案仍须暂停询问。
- 已确认或工业模式授权定稿的造型自动沿连续性组继承；只有换装、状态变化或冲突时按当前场模式重新处理。
- 不主动输出颜色、面料、品牌、剪裁和装饰等详细视觉设计，除非用户另行要求。
- 为保证编号可识别，至少记录上装、下装、外套、鞋履、帽子、关键配件或用户提供的服装参考图编号；没有的项目写“无”。这只是识别锚点，不扩展为详细设计稿。

### 造型最小化原则

- 在剧情时间、天气、人物身份和行动条件允许时，默认沿用已经确认的服装；没有明确叙事功能时，不主动设计换装。
- 同一连续性组内默认不换装。跨场只更新穿脱、湿污、破损、血迹和持有位置等状态，不新建造型编号。
- 时间跳跃本身不自动触发换装；只有剧本明确、用户要求，或睡眠、制服、正式场合、季节天气、严重湿污破损等条件确实要求时，才提出新造型。
- 不为了丰富画面、表现情绪、区分场次或展示服装能力而换装。
- 同一人物跨年龄、跨多年或身份明显改变时，不强行保留完全相同的衣服；优先保留1—2个角色识别锚点，例如稳定的整体轮廓、常用配件、穿着习惯或用户确认的视觉特征。

### 角色识别锚点

每个主要人物至少记录1个、至多3个稳定锚点：

```markdown
| 人物 | 主要服装编号 | 稳定识别锚点 | 允许变化 | 禁止无理由变化 |
|------|--------------|--------------|----------|----------------|
```

- 锚点服务人物识别与AIGC一致性，不要求所有年龄和时间线穿同一套衣服。
- 新造型必须说明旧锚点保留了什么、为何必须变化；无法说明必要性时沿用旧造型。

## 2. 服装编号

基础造型使用：`人物-C01`、`人物-C02`。

只有基础造型真正改变时创建新编号。穿脱、湿污或破损属于同一编号下的状态变化，不创建大量新编号。

```markdown
| 服装编号 | 人物 | 造型用途 | 首次场次 | 适用连续性组 | 初始状态 | 锁定状态 |
|----------|------|----------|----------|--------------|----------|----------|
```

每个编号另记录最低识别锚点：`上装 / 下装 / 外套 / 鞋履 / 帽子 / 关键配件 / 参考图编号`。

## 3. 功能性设计字段

- 造型用途：日常 / 工作 / 正式 / 睡眠 / 行动 / 特殊任务。
- 季节和天气适配。
- 室内外适配。
- 动作适配：奔跑、打斗、驾驶、睡眠等。
- 是否需要外套、鞋履、帽子或剧情相关配件。
- 是否具备换装条件。
- 与人物身份和场次功能是否一致。

## 4. 状态词表

- 穿着 / 脱下 / 披着 / 拿在手中 / 放置于指定位置。
- 干燥 / 潮湿 / 湿透。
- 整洁 / 轻度污损 / 重度污损。
- 完好 / 轻度破损 / 明显破损。
- 无血迹 / 少量血迹 / 明显血迹。
- 状态未知。

衣物上的雨水、泥污、血迹和其他附着物归服装系统；身体、面部和头发上的同类状态不写入服装状态。

变化记录必须包含：发生镜头、动作原因、变化后状态和后续继承目标。

## 5. 写入正式分镜的条件

静态穿着不在每镜重复。只有以下情况写入画面内容：

- 穿上、脱下、拿起或放下衣物；
- 被雨水或其他液体打湿；
- 被撕破、磨损或弄脏；
- 血迹或剧情物质附着；
- 服装参与、帮助或妨碍动作；
- 服装状态本身承担剧情信息。

其余状态只在连续性总表中维护。

## 6. 连续性检查

- 是否在没有剧情必要时建立了新服装编号；若是，撤销换装并沿用原造型。
- 新造型是否保留了已确认的角色识别锚点，或有充分理由改变。
- 连续场次是否无理由换装。
- 外套、帽子、鞋履和配件是否消失或复位。
- 湿润、污损、破损和血迹是否错误恢复。
- 脱下的衣物是否仍在正确位置或由正确人物持有。
- 时间跳跃是否足以支持换装、清洗或修复。
- 同一动作覆盖是否使用同一动作阶段的服装状态。
