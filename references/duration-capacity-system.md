# Duration / Capacity Engine（时长与容量系统）

本文件定义 Storyboard 项目的模型无关时长估算、镜头容量复核和生成段容量检查。它服务导演判断，不替代正式分镜，也不授予改写剧本、对白或镜头结构的权限。

## 1. 两种时长必须分开

### 1.1 银幕时长（Screen Duration）

正式分镜中一个镜头或一场在最终剪辑时间轴上自然成立所需的预计时长。它由对白、动作、停顿、表演、走位、空间建立、信息辨识与镜头读取共同决定。

### 1.2 生成段容量（Generation Capacity）

具体视频模型或用户工作流允许的一次生成时长上限。只有用户、当前适配模块或平台资料明确给出时才启用；未给出时不得自行假设 10 秒、15 秒、30 秒或其他平台上限。

**银幕时长不是生成段上限。** 一场可以有 48 秒银幕时长，同时被执行为多个生成段；也可以保持一条完整派生提示词，只在实际生成阶段拆分。是否拆分由当前适配器和用户授权决定，不反向修改正式分镜。

## 2. 权威边界

容量判断按以下信息工作：

1. 原剧本逐字对白与必须发生的动作；
2. 用户已经确认的表演、走位、停顿、情绪落点与镜头结构；
3. 第②步简稿或第⑤步正式分镜中的镜头时长；
4. 用户明确指定的总时长、单镜时长或生成段上限；
5. 当前适配模块明确提供的平台能力。

不得为了“装进时长”擅自：

- 删、改、缩写或加速对白；
- 删除必要反应、动作结果或剧情信息；
- 把必须串行的动作假装同时发生；
- 新增无功能的沉默、微动作、空镜来凑时长；
- 改变已确认镜头数、主要景别、主运镜或对白分配。

涉及上述结构变化时，返回第②步；正常模式由用户确认，工业模式按本场已选择的授权在内部调整并重新预检。容量引擎本身不提供改镜头权限，任何模式都不得因此改写剧本或已锁定事实。

## 3. 对白基础校准

对自然普通中文口语，可用 **每秒约 3.5—4.2 个有效汉字**作为第一轮容量校准起点：

```text
对白基础时长区间 ≈ 有效对白字数 ÷ 4.2  ～  有效对白字数 ÷ 3.5
```

这是校准区间，不是演员必须达到的语速。

- “有效对白字数”只统计实际说出的文字，不把人物名、场景标头、动作描述和标点计入。
- 情绪性迟疑、哽咽、强调、重音、真实听说反应会增加时长，应依据已确认表演调整。
- 用户或剧本明确要求快速、缓慢、机械、广播式等特殊说法时，以该表演要求为准，不机械套基准区间。
- 外语、数字串、专名、技术词或复杂实体文字无法由汉字速率可靠估算时，标记为需人工复核。

## 4. 非对白容量组成

逐镜估时除对白外，按适用性检查以下项目：

| 类别 | 典型内容 | 规则 |
|---|---|---|
| 必要停顿 | 听完后的反应、决定前停顿、情绪落点 | 有叙事功能才计入，不人为加停顿凑时长 |
| 串行动作 | 起身→走到门边→开门；拿起→查看→放下 | 有明确先后依赖时必须顺序计时 |
| 可重叠动作 | 边走边说、说话时整理衣物 | 只有画面真实可同时发生且都能读清时才能重叠；分别记录动作之间重叠和对白—动作重叠 |
| 走位与空间 | 横穿房间、上楼、绕过障碍、人物换位 | 距离未知时给定性区间，不编造精确米数 |
| 信息辨识 | 看清手机内容、道具异常、人物发现 | 观众必须读懂的信息要留读取时间 |
| 倾听与反应 | 对方台词后的可见/可听反应 | 服从人物表演系统，不抢关键台词 |
| 建立与重定向 | 新空间建立、方向重建、时空转换 | 仅在镜头承担该功能时计入 |
| 摄影机读取 | 大幅摇移、复杂跟拍、焦点转移后的信息读取 | 只计算可见叙事功能，不把运镜本身当装饰时长 |
| 状态变化结果 | 门打开后状态、物品破损、光源熄灭 | 必须让结果可确认时计入 |
| 武戏动作段落 | 发起、对方应对、接触或落空、失衡、恢复、重新定位 | 先确认哪些阶段串行、哪些真正重叠，再估算；剧本只概括过程时以用户已接受的动作方案为依据，不用脚本编造招式或默认动作速度 |

## 5. 容量计算原则

内部使用下面的逻辑，不必向用户伪装成精确数学模型：

```text
动作有效时长
= 非对白组件总和 - 已确认的动作—动作重叠

自然所需时长
≈ 对白基础时长 + 动作有效时长 - 已确认的对白—动作重叠
```

同时保留合理表演余量。估算优先输出区间，而不是单点精确值。

### 重叠的物理下限

- `action_action_overlap_seconds` 只表示动作组件之间确实同时发生的部分。动作有效时长不得短于最长的单个非对白组件；无论填入多大的重叠值，纯动作镜都不能被扣成 0 秒。
- `dialogue_action_overlap_seconds` 只表示动作有效时长中可与对白同时发生的部分，并分别受对白时长和动作有效时长限制。
- 旧输入 `confirmed_overlap_seconds` 为兼容字段，只按“动作—动作重叠”保守解释；不得与 `action_action_overlap_seconds` 同时提供。
- 不知道并发关系时按串行计算，不用一个总重叠数模糊抵扣不同类型的时间。

### 容量状态

- `充裕`：已给时长能够自然完成内容并保留必要表演空间；
- `可行但偏紧`：理论可完成，但需要较紧节奏，必须确认不牺牲已确认表演与读取；
- `过载`：即使采用合理重叠，也无法自然完成权威对白和动作；
- `不确定`：距离、表演速度、复杂动作或平台能力缺失，无法可靠判断。

不得把“过载”通过倒填更短时长改成“可行”。

## 6. 单镜容量卡

第②或第③步需要时，在内部或简报中使用：

```markdown
### 镜头 X-Y 容量检查
- 已声明/拟定银幕时长：
- 有效对白字数：
- 对白基础时长区间：
- 必须串行动作/走位：
- 必要停顿/反应/信息辨识：
- 可确认重叠：
- 自然所需时长区间：
- 容量状态：充裕 / 可行但偏紧 / 过载 / 不确定
- 主要依据：
- 若需调整：仅列可选方案，不自动修改
```

完全无对白、动作简单且明显可容纳时可只给一句简版结论，不机械展开表格。

## 7. 单场容量检查

### 第②步：简稿预检

镜头结构提出后、进入正式分镜前：

1. 为每镜给出合理预计时长或区间；
2. 检查对白是否在单镜中有自然说完空间；
3. 检查动作、表演、走位、信息读取是否与镜头时长匹配；
4. 累加得到本场预计银幕时长区间；
5. 若用户有明确场次目标时长，比较差异并解释原因；
6. 若存在过载镜头，先指出冲突，再提出可选的镜头结构调整方案；增删、合并、拆分、主要景别/运镜改变或对白重新分配均须返回第②步，正常模式重新确认，工业模式内部调整并重新预检。

### 第③步：正式预览复核

按照实际写出的对白、动作与表演重新检查，不得只沿用简稿数字。发现过载且需要改变镜头结构时返回第②步，按当前场模式确认或内部返工；仅需把明显不合理的预计时长改成更真实数字、且不改变导演意图时，正常模式列为待确认修正，工业模式可内部修正并在第⑤步复核。

### 第⑤步：定稿复核

最终写入前重新核对全部逐镜时长：

- 每镜时长与最终正文是否一致；
- 本场总时长是否等于逐镜时长之和；
- 没有通过压缩对白、动作或必要反应制造虚假的短时长；
- 正常模式已确认、或工业模式内部复检通过的容量修正已经进入正式版本。

定稿后，正式分镜中的时长成为下游派生输出的银幕时长依据。

## 8. 生成段容量

只有存在明确单次生成上限时执行。

### 8.1 先比较，不自动拆

```text
本场/当前执行范围银幕时长
vs.
当前生成段容量上限
```

未超限：正常编译。

超限：说明超出量和可用自然边界；不得仅为了平台限制修改正式分镜。

只有银幕时长本身有效时，才用已声明银幕时长判断生成段是否超限。银幕容量已经判为`过载`时，生成状态必须写`待修正银幕时长`，不得因为错误声明值小于平台上限而写`未超限`。

同时用自然所需时长区间给出独立风险：

- 自然最短时长也超过平台上限：`确定冲突`；
- 只有自然最长时长超过平台上限：`可能冲突`；
- 自然时长区间均未超过：`暂无冲突`。

这些状态只描述执行适配风险，不授权压缩银幕时长、改剧本或拆镜。

### 8.2 自然分段优先级

在不改变正式镜头的前提下，优先选择：

1. 已完成的一句或一轮对白之后；
2. 一个动作因果链完成之后；
3. 发现、反转或信息落点之后；
4. 情绪阶段完成之后；
5. 正式镜头边界。

不得截断一句对白、一个未完成的关键动作或一个必须连续完成的镜头运动。

如果**单个正式镜头本身**超过当前模型单段容量，报告适配冲突；除非用户明确授权回到第②步改变镜头结构，否则不擅自拆镜。

### 8.3 分段不改变事实源

执行段只是派生生产计划：

```text
正式分镜（镜头事实源）
→ 执行段分组/适配
→ 模型提示词或生成任务
```

执行段的边界、平台参数和失败返工不得自动写回正式镜头事实。

## 9. 与 Seedance 编译的关系

Seedance 编译必须读取本模块，并区分：

- `本场预计总时长`：来自正式分镜逐镜时长之和；
- `当前生成段容量`：只有用户或平台明确指定时存在；
- `容量冲突`：提示词结构无法解决正式内容超出平台单段能力的问题。

若当前 Seedance 工作流仍采用“一场一条完整提示词”，容量引擎只负责报告平台执行风险，不因此自动把正式提示词拆成第二套镜头版本。用户明确要求按生成段输出时，再按照当前适配规则派生执行段。

## 10. 脚本辅助与人工判断

[`estimate_capacity.py`](../scripts/estimate_capacity.py) 可以做确定性的基础换算和汇总：

- 中文对白基础时长区间；
- 已提供的串行动作、停顿、走位、信息读取、反应与摄影读取时间合计；
- 已确认的动作—动作重叠和对白—动作重叠，且始终保留物理下限；
- 与用户声明时长的基础比较。
- 将 `declared_seconds`（正式或拟定银幕时长）与可选的 `generation_limit_seconds`（明确生成段上限）分别判断；二者不得共用同一状态字段。银幕过载时先修正银幕时长，再判断声明值是否超过生成段上限。

脚本不知道戏剧节拍、表演真实性、空间距离和观众是否真的读得懂信息，因此：

武戏容量还须由导演判断动作阶段是否可辨、人物能否从前一状态完成下一动作、受力和结果是否有读取时间；`estimate_capacity.py` 不具有推导动作编排或自动提高动作速度的权限。

**脚本结果只能作为预检证据，最终容量状态仍由本系统结合剧本、表演与镜头语境判断。**
